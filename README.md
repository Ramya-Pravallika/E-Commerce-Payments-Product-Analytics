# E-Commerce & Payments Product Analytics

An end-to-end analytics project built on the public Olist Brazilian E-Commerce dataset. It downloads the source data directly with KaggleHub, builds an indexed SQLite warehouse, computes customer and operations analytics, fits statistical models, simulates a checkout experiment, and presents results in an interactive Streamlit dashboard. The Power BI semantic-layer guide remains available in [powerbi/olist_powerbi_dax.md](powerbi/olist_powerbi_dax.md).

## Quick start

Use Python 3.10 or newer. Install the dependencies, then run:

```powershell
pip install -r requirements.txt
python init_db.py
streamlit run app.py
```

The first pipeline run downloads all eight official CSV files through KaggleHub, so Kaggle access may require account/API configuration depending on the environment. No local CSV folder is required. The database is written to `olist_analytics.db` next to the scripts. To use a different output path, pass `--db path/to/database.db` to `init_db.py`.

## Deploy to Streamlit Community Cloud

1. Push this repository to GitHub.
2. In Streamlit Community Cloud, create an app from this repository, select the `main` branch, and set the app entry point to `app.py`.
3. Deploy. The SQLite file is intentionally not committed; on first launch the app downloads the public Olist dataset through KaggleHub and builds the local warehouse automatically, importing one CSV at a time to reduce peak memory.

The first cold start therefore needs outbound network access and enough deployment disk space for the Kaggle dataset and generated database. Later reruns use the generated local database. If the hosting instance is rebuilt, the database is ephemeral and will be regenerated on its next start. The project does not require MySQL credentials or Streamlit secrets.

## Included analytics

- Indexed SQLite raw tables for customers, geolocation, orders, items, payments, reviews, products, and sellers.
- SQL CTE/window-function metrics: monthly delivered GMV, order count, AOV, month-over-month GMV growth, payment volume/value share, payment installments, and a purchase-to-delivery funnel.
- SLA breach rates and delay/delivery duration by destination state, with ZIP geolocation-based map markers.
- Unique-customer monthly cohort retention and quartile-scored RFM segments: Champions, High-Value Loyal, At Risk, Lost, and Standard.
- Order-level robust OLS delay model (approval hours and freight value) and logistic low-review model (late-delivery indicator and payment value). These are observational associations, not causal effects.
- A two-proportion z-test simulator with configurable baseline, MDE, alpha, power, Wilson rate intervals, an approximate lift interval, sample-size calculation, and explicit launch criteria.

## Streamlit pages

1. **Executive Summary** — selectable date/state filters, GMV/orders/AOV trends, payment mix, state SLA bars, geospatial hotspots, and funnel/duration exploration.
2. **Cohorts & RFM** — adjustable retention horizon, cohort heatmap, segment value charts, and customer-level RFM drill-in.
3. **Regression Drivers** — model diagnostics and coefficient/odds-ratio confidence intervals.
4. **A/B Testing Simulator** — sidebar assumptions and observed variant inputs update the sample-size estimate, significance test, interval visualization, and recommendation.

## Notes

- `olist_analytics.db` is generated locally and excluded from Git; rebuild it with `python init_db.py` when needed.
- KaggleHub download and initial CSV ingestion require internet access and sufficient local disk space.
- Statistical models may take a short time to fit on first load; dashboard query results are cached for 15 minutes.
